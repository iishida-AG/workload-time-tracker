# Two-User Realtime Workload Design

## 目的

石田・田上の2人がそれぞれ自分の入力ページで日次予定・実績・メモを保存し、相手の入力内容をリアルタイムで確認できるようにする。週次・月次振り返りでは、大分類ごとの目標、実績、話し合いたいことを同じ画面で確認できる状態にする。

## 追加パッケージ

```bash
npm install firebase
```

## Firebase方針

- Firebase Hostingで静的Webアプリを公開する。
- Cloud Firestoreを共有DBとして使い、2人分の入力内容をリアルタイム購読する。
- Firebase Sparkプランの無料枠運用を前提にする。
- Firestore設定値は `src/firebase-config.js` に置き、実プロジェクト値はデプロイ前に差し替える。
- 課金や権限事故を避けるため、Firestoreルールは石田・田上の運用範囲に限定する前提でREADMEに注意を書く。

## データ構造

既存の `AppState` に次の概念を追加する。

- `users`: 固定値として `ishida` と `tanoue` を持つ。
- `timelineSettings`: `{ userId, date, startHour, endHour }`
- `dayPlans` / `dayActuals`: 既存の `{ date, hour, taskId, note }` に `userId` を追加する。
- `weeklyProjectGoals`: `{ userId, weekStart, projectId, goalText }`
- `monthlyProjectGoals`: `{ userId, month, projectId, goalText }`
- `weeklyReviews`: 既存項目に `discussionItems` を追加する。

既存ローカルデータには `userId` が無い可能性があるため、読み込み時は現在選択中ユーザー、または `ishida` として補完する。

## 画面設計

### 日次入力

- 上部に `石田` / `田上` の入力ページ切り替えを追加する。
- 自分のページでは予定・実績を入力して保存できる。
- 右側または下部に相手の同日予定・実績の読み取りプレビューを表示する。
- 日次スケジュールは日ごと・ユーザーごとに開始/終了時間を選べる。
- 予定/実績セルは `タスク名 + 自由記入欄` を持つ。
- セルを選択した状態でBackspaceを押すと、そのセルのタスクと自由記入欄を削除する。
- 予定と実績それぞれに、1日分のコピー用テキストを表示する。
- コピー用テキスト形式は `9:00-10:00 エンジニア提案：「自由記入欄」` とする。

### 週次目標と実績件数

- 日次画面の一番下に移動する。
- 数値目標ではなく、大分類ごとの自由記入目標に変更する。
- 実績件数は大分類ごとに配下の件数管理タスクを合算して表示する。
- 石田・田上の入力ページごとに、自分の週次目標と実績を表示する。

### 振り返り

- 月次目標設定を、大分類ごとの自由記入欄として表示・編集する。
- 週次/月次の集計は、石田・田上それぞれと合計を見られる形にする。
- 振り返りフォームに `話し合いたいこと` の箇条書き欄を追加する。
- `来週の改善約束` は既存どおり翌週の日次画面上部に表示する。

## リアルタイム同期

- Firestore利用時は `onSnapshot` で共有状態を購読する。
- 保存時は該当ドキュメントを更新する。
- Firebase設定が未入力のローカル開発では、既存の `localStorage` 保存にフォールバックする。

## テスト

- ユーザー別タイムラインが混ざらないこと。
- 日別開始/終了時間から時間枠が生成されること。
- Backspace削除で選択セルのタスクとメモが消えること。
- 大分類ごとの週次実績件数が正しく合算されること。
- 月次目標と話し合いたいことが保存されること。
- コピー用テキストが指定形式で生成されること。

## 非対象

- Firebase Authenticationの本格ログイン実装は今回の範囲外とする。
- 同時編集の細かな競合解決UIは今回の範囲外とし、最後に保存された内容を正とする。
